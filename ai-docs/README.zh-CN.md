# 给 AI 阅读的文档 · [English](README.md)

[仓库首页](../README.zh-CN.md)

本目录收集给新接手项目的 AI agent 阅读的入门指南、设计要求、方法说明与交接文档。每个主题提供完整的中英双语版本，并带有语言切换及参考链接。

这些是阅读材料，不是 `AGENTS.md` 配置，也不是新增的已形式化定理集。设计偏好、条件性论证、研究猜测与实际完成的实现或形式化结果，应始终明确区分。

## 文档目录

1. **设计基本列型序数记号的美观性** — [中文](fundamental-sequence-aesthetics.zh-CN.md) · [English](fundamental-sequence-aesthetics.md)。本目录的第一份指南，面向对序数记号尚不熟悉的新 GPT‑6 Astra agent。介绍列序列语法、末列展开、基本列前缀嵌套、兼容可达域、精确局部计数与字典序比较、简单的单列内容、实质强度提升、证明义务及交付要求。包含计数序列论证、示例、验收清单和可直接转交的任务说明。

## 两个实际入口

- **[用户的 GitHub 仓库](https://github.com/hzyhhzy/column-ordinal-notations-hzy)** 用于参考记号定义、实现和证明思路。可以先读[仓库总览](../README.zh-CN.md)，再查阅[纸面证明](../proofs/paper/)和 [Lean 说明](../lean/README.zh-CN.md)。参考已有材料，不意味着必须照搬旧系统或受其强度限制。
- **[NER / ne-rewritten](https://smilelee-lyx.github.io/ne-rewritten/)** 是用户在记号完成后实际查看、操作和展开的平台。因此面向网页的交付应包含兼容其自定义记号接口的 JavaScript 展开器，以及适合该结构的列表、计数等显示；只交论文或 Python 核心，不等于完成了这部分界面工作。数学规则本身独立于网页。

## 后续文档的放置约定

- 每个主题独立命名：英文为 `topic-name.md`，中文为 `topic-name.zh-CN.md`；两种语言都应完整，内容保持同步。
- 首行标题链接到另一语言，并提供返回本目录和相关定义、证明、工具的链接。
- 在两份目录中同时登记新主题。仓库内文件使用相对链接，外部资源使用明确的 HTTPS 链接，不放机器专用路径。
- 说明面向的读者、用途、前置知识、日期或版本，以及已知结果与提案的边界。保留“结构合法输入”与“标准可达式”等重要区别。
- 设计指南放在这里；具体记号的定义和展开器仍放在 `notations/`，比较研究放在 `research/`，证明产物放在既有证明目录。新增指南不改变它们的内容或证明状态。
- 本集合以 Markdown 为主；加入一篇指南本身不要求生成 PDF 或新增 Lean 项目。在仓库根目录运行 `python tools/check_release.py`，可将语言配对、本地链接与既有发布条件一起核对。

本目录目前有一个主题、两种语言。以后可以独立加入其他给 AI 阅读的文档，不干扰现有记号的实现和证明。
