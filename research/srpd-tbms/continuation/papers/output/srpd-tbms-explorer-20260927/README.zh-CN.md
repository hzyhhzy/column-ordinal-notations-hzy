## 范围与使用

左侧起点记作

\[
E=\mathrm{TBMS}\;()(1^{\varepsilon_0})=()(1^{()(1,1)}).
\]

这里 ε₀ 是 TBMS 的行高度标签，不是说 E 本身的序数只有 ε₀。
展开按钮展开的是左侧 **普通 TBMS 的默认基本列**；右侧显示该源状态的 SRPD 上界。
范围仅为从 E 有限次展开可达的标准式，**不是整个 TBMS，也不是任意手写的较小字符串**。

可直接输入 `E`、`E[2][0]`、`E[3][1][0]` 等路径。默认视图的纯文本末尾也保留
`@ E[...]`，复制后可解析还原。单独一个 TBMS 式子不能确定原来的持续模拟历史，
所以“TBMS 原式”视图不提供不可靠的反向路径猜测。

本文件有六种显示：

| 显示 | 右侧内容 | 沿源展开持续下降？ |
|---|---|---|
| 对照·计数（默认） | 当前历史的 SRPD 计数序列 | 是，指数学模拟；超限时不提供对应 |
| 对照·父列表 | 同一状态的 SRPD 父列表 | 同上 |
| 重选起点·计数 | 为当前 TBMS 式子重新建立的覆盖 | 不保证 |
| 重选起点·父列表 | 重选覆盖的 SRPD 父列表 | 不保证 |
| TBMS 原式 | 仅显示原生 TBMS 表达式 | 采用原生 TBMS 比较 |
| 展开路径 | `E[n][m]…` | 用于精确重现历史 |

列表和计数采用页面继承字体。TBMS HTML 保留原生上标。
所有 FS 接口采用**同一默认规则**，没有混用 TBMS 的缩短基本列。
NER 排序只看 TBMS 原式，不按照右侧 SRPD 显示结果排序。

## 1. 沿历史持续模拟

默认程序移植既有的 对称塔承载算法（未随本次收录的来源：`output/tbms-e0mn-bridge-20260925/symmetric-tower-cover.cjs`）
及其 [纸面下降模拟](../tbms-e0mn-bridge-20260925/SYMMETRIC-TOWER-BOUND.zh-CN.md)。
0、1 阶使用该文 §10 的有限行模拟；一般阶使用多项式底层加 CNF 上层的持续覆盖。
[通用覆盖算法](../../../../archive/output/tbms-e0mn-bridge-20260925/epsilon-row-cover.cjs)
仅作为公共辅助函数和重选一般式子的后备初始化，不再作为默认对角种子。

SRPD 起点是更新后的 `[0]`，计数为 `2`。公共根不显示。
本文件内嵌的是最新 [SRPD.ne-rewritten.js](../../../../../../notations/SRPD/SRPD.ne-rewritten.js)，
所有有限目标基本列操作最终均调用这份 SRPD 的实际展开规则。
不会再补旧版的首空列或额外的首个 `1`。

第一次 `E[h]` 的目标为对称式 Wₕ：

\[
W_0=(1,2),\qquad
W_h=(1,2,4,\ldots,2^{h+1},2^h,\ldots,4,2)\quad(h\ge1).
\]

以上是计数显示，不是用计数猜测内部父图。
父表为 `[][1][2,2]…[h+1,…,h+1][h,…,h]…[1]`，
程序沿纸面文稿 §2.1 的真实下降路径从 SRPD 起点得到它。

| TBMS 节点 | SRPD 对称承载的计数 |
|---|---|
| `E[0]=()(1)` | `1,2` |
| `E[1]=()(1^ω)` | `1,2,4,2` |
| `E[2]=()(1^(ω^ω))` | `1,2,4,8,4,2` |
| `E[3]`（行标签三层 ω 塔） | `1,2,4,8,16,8,4,2` |
| `E[5]`（行标签五层 ω 塔） | `1,2,4,8,16,32,64,32,16,8,4,2` |

这些起点比上一版的 `SRPD[2h+3][max(1,h)]` 更紧。
不由此宣称每个后续式子的新显示都小于旧显示，更不宣称两边等号。

当 h≥2，下一步 `E[h][t]` 才确定底层多项式次数 d=t+1。
程序在**保留的 Wₕ** 上执行

\[
W_h\left[\left\lceil\frac{t}{2h+1}\right\rceil\right]
\]

并建立 h−1 层字典；以后所有指标继续使用同一个目标后代。
当 h=1，`E[1][t]` 有 t+1 条单位行，采用
`W₁[max(0,ceil((t−1)/3))]` 的有限行祖先覆盖。
h=0 时则与 W₀ 的有限空列后代逐步一致。

后续每个源步骤，都从上一步的**同一个实际目标**继续下降。
目标操作包含普通基本列步和局部下降宏；后者表示已经证明可由有限多步基本列实现的
精确端点，并不是新加的任意改写规则。为了效率，不枚举可能极长的逐步微观轨迹。

这不是一个与历史无关的保序嵌入。同一个 TBMS 式子通过不同路径到达，右侧可以不同。
大小符号采用已有纸面工作的**基本列下降秩**口径；不声明逐指标交换、全域保序或序型相等。
本次任务没有补出反向 SRPD→TBMS 嵌入，也没有恢复原先暂停的等号证明目标。

## 2. 重选起点

重选视图不读取旧的区间字典，只对**当前源式**重新选择已有承载方案。

优先识别以下已证明特例：

- 源式本身是 Sₕ：直接选 Wₕ。
- 源式是 Sₕ 的第一分支 `B_(Θ_(h−1)(d))`：使用对称承载的对应初始化。
- 源式是有限条单位行的两列种子：使用 W₁ 后代的有限行覆盖。

这使得沿旧路径降成 S₁ 的节点可以重新选到 `1,2,4,2`，
而不是仍用旧版的 `1,2,4,8,15`。
**不能识别为这些特例的一般式子，仍用通用局部对角覆盖**：

1. 读取各列的累计行端点（ε₀ 以下 CNF）。
2. 取最小的有限塔高度 h，使全部当前端点不超过 τₕ，其中 τ₀=1、τₕ₊₁=ω^τₕ。
3. 递归补齐这些端点的 CNF 前缀和下层指数。
4. 调用既有 `initializeForSource`，从 SRPD 起点的一个真实标准对角后代建立新覆盖。
5. 检查整个覆盖不变量；检查通过才显示结果。

新的上界沿用纸面证明“任一满足覆盖不变量的状态可继续模拟”的论证，
不需要假装它是此前那个目标的后代。
空源式直接取 SRPD 的零；顶端 E 仍以 SRPD 起点作上界。

重选不是最小化算法：没有搜索全部 SRPD 式子，也没有声称得到最紧上界。
它既可能更小，也可能更大，沿源展开还可能增加。

例如 `E[2][0]=()(1^ω)`：

```text
持续模拟：1,2,4,8,4
重新覆盖：1,2,4,2
```

在新版 SRPD 的父列表比较下，第二项确实较小。
而 `E[2][1][1]=()(1^ω,1^ω)` 的重选结果反而大于持续模拟结果。
这些例子说明“更短的打印结果”“更小的计数”不能替代记号本身的比较。

持续模拟与重选视图完全独立：切换显示不会更换持续模拟的起点，也不会污染分支状态。

## 3. 计算保护

每次模拟约 0.9 秒软保护，辅以工作量、宽度、格数、递归深度和有界缓存。
目标最多 768 列，父表最多 160,000 格；初始／重选塔高度保护为 24。
这些都是网页实现的计算预算，**不属于数学定义或定理的范围限制**。

超限时显示 `?（模拟未算出：原因）`，不换更大起点、不伪造对应；仍可继续展开源 TBMS。
真正的不变量错误会另外显示“模拟校验失败”，不被归类为计算超限。
SRPD 计数使用 BigInt，超出计数预算时保留已知列，其余写 `?`。

表达式本身仅存 JSON 可序列化的路径。缓存可丢弃，并可从同一路径重新计算；
不依赖不持久化的 Map 或页面全局变量。内部状态的 Map 及共享节点会正确复制，
不同子分支互不修改。

## 4. 核验与复现

verify.cjs（未随本次收录的来源：`output/srpd-tbms-explorer-20260927/verify.cjs`） 对**最终独立文件**在无 DOM、无 require 的注册环境中运行：

- 111 次源端默认展开与缓存的原生 TBMS 实现一致；同时检查默认／两个别名、比较和 JSON 重载。
- 8 个对称起点核验计数与内部父表，覆盖高度 0…5、8、12。
- 151 个持续模拟步骤与原对称模拟器／独立有限行实现一致，覆盖初始塔高度 0…6 的有界路径。
- 206 个目标下降事件独立验证，其中 70 个为局部下降宏，由既有精确轨迹证书核验；
  还逐事件检查“上一次终点恰是下一次起点”，防止中途偷偷重新初始化。
- 8 个重选实例分别检查对称特例或通用覆盖，并做 12 次独立后续展开。
- 检查兄弟分支隔离、失败后父状态不变、无缓存重算和源端在模拟超限后继续展开。

原型的 14 次宽度停止明确记录为停止，不算已完成的步骤。
测试是实现核验，不替代全称纸面证明；没有新增 Lean 定理。
报告见 VERIFICATION.json（未随本次收录的来源：`output/srpd-tbms-explorer-20260927/VERIFICATION.json`）。测试进程已退出，不留后台搜索。

构建和测试：

```powershell
node --max-old-space-size=512 output/srpd-tbms-explorer-20260927/build.cjs
node --max-old-space-size=512 output/srpd-tbms-explorer-20260927/verify.cjs
```

`runtime.js` 是编辑源；`build.cjs` 自动内嵌 SRPD、编译原生 TBMS，并打包既有模拟器。
TBMS 加入运行预算检查，但不改变数学分支；移除上游无界缓存，采用有界缓存。
来源文件的 SHA-256 写入最终文件 `debug.provenance` 和核验报告。
