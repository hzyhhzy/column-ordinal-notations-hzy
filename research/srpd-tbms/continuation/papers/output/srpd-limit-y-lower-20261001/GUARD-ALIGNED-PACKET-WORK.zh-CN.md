## 更宽的工作接口

在 P 内进一步要求，每个仍封闭块根 c 的正父恰为它的高1保护根 r，
而每个非私有的直接底行孩子 j 满足

\[
H_j=\varnothing,\qquad
P_j=(c)\quad\text{或}\quad P_j=(c,r).
\tag{1}
\]

私有第一尖端 u 不受式 (1) 限制，仍为父表 \((c,c,c)\)、高父 c。
称此类为 L。旧 J 只允许式 (1) 的第一种，并额外要求连续块列；
L 允许第二种，因此允许同一个 r 上的封闭 c 沿底行串联。
L 不省略 P、H 的规范性、私有性、颜色、标记和严格零星条件。

对原普通底父树，从每个普通高≤1的列重新开始记录：

\[
D(j)=
\begin{cases}
(),&h_j\le1;\\
D(P_j(0))\frown\bigl(P_j(0)\bigr),&h_j>1\text{ 且底父是仍封闭块根};\\
D(P_j(0)),&\text{其他情形}.
\end{cases}
\tag{2}
\]

只在封闭块根 c 上读取它。D(c) 中每个块根的保护根都是同一个 r。
因为每越过一个非私有孩子，式 (1) 要么已经以高1重新起算，
要么保持同一行1分支；而任何封闭 c 的行1父又恰为自己的高1保护根。
所以式 (2) 实际记录的是同一保护根内的封闭祖先，不记录跨保护根的嵌套。

## 工作接口在原展开下保持

首先，尚封闭 c 的额外普通孩子不能被外部高步抬高。
对于式 (1) 的高2孩子，行≥2在入口终止；行1的父链直接到仍封闭 r，
只有以 r 为活动根的高步才可能改写，而它在私有叶仍存在时不能执行。
高1孩子由旧一行屏障保护，行0高步仍由严格零星接口处理。
尚封闭 c 本身的高度和正父同样受保护。

再看可能新生的直接孩子。普通行0首接缝继承旧切点的父表，故式 (1) 保持。
普通正行接缝若底父为封闭 c，则旧末列就是 c 的直接普通孩子。
它不可能高1并有正行；若为 \((c,r)\)，只能在行1切 r，产生的新首根高1，仍符合式 (1)。
高步首接缝要连到封闭 c，必须以 c 为活动根；其私有 u、t 后面还有 e，排除此控制。
其余列按整份复制搬运，没有新边界例外。

开启末私有 e 时，只有该 c 失去封闭身份。该步没有仍留在 e 右侧的工作列，
因此不会把它的后方子块无代价提升成新的外层封闭块。
其他私有块整段保留或复制。H 与 P 的闭包处理其余普通、高父及标记条件。
所以 L 对所有原基本列指标闭合，截前缀也闭合。

## 存活局部栈逐列保持

设一步控制切点为 a，复制跨度为 Δ，第 b 份的列搬运为
\(\phi_b(p)=p\)（p<a），否则 \(p+b\Delta\)。
对每个完整存活的封闭块 c，都有

\[
\boxed{D'(\phi_b(c))=\phi_b(D(c)).}\tag{3}
\]

保留列取 b=0。被消耗末叶所属的 c 不再封闭，不列入式 (3)。

普通行0切封闭 c 时，新首根继承 c 原底父，故不会多接前一份 c；
其余局部栈逐列递推。普通正行不能在仍封闭 c 处切入它的工作：
式 (1) 的行1祖先直接绕过 c 到 r，行≥2已被入口屏障截断。
若正行在 r 开启私有叶，新复制 r 高1，局部栈重新为空；
复制区内的剩余封闭祖先均在这个 r 之后，恰好逐份搬运。
更早的封闭块不能越过这个高1屏障混入新栈。

高步对仍封闭的 c、r 及其工作入口由上一节的屏障处理：
它们不被升行；完整搬运仍保留同一个保护根内的祖先链。
高1保护根在其私有结构仍完整时不能被高控制消去这一屏障。
旧高1私有枝开启时，其右方已没有引用该根的封闭块，故不产生遗留栈的例外。

由式 (3)，

\[
d(s)=\max_{c\text{ 仍封闭}}|D(c)|,
\qquad d(s[n])\le d(s).
\tag{4}
\]

没有额外封闭块时最大值约定为−1。式 (4) 不要求每步严格下降。

## 尾部16 7及归纳的实际边界

写 U=(1,3,4,2,5,8,10)、C=(4,9,14,16)。
[原控制公式](NEXT-PACKET-CHAIN.zh-CN.md)给

\[
V_7[n]=U\frown\mathop{\frown}_{b=0}^n(C+2b).
\]

每个子项属于 L，且 d 恰为 n。由闭包和式 (4)，
它的全部合法后代都保留这个局部界。
一次开启虽可令旧全局深度任意增长，却不会破坏本稿的局部栈运输。

这仍然不能直接把旧 J 证明中的全局 d 换成新局部 d。
J 的任意全局深度都可落在 L 的局部深度0中：J 的每个封闭块父为 \((r,r)\)，
其额外工作入口全部高1，所以每进入另一个工作组件就重新起算。
特别是全部 V6[n] 都在这个局部深度0层，但旧证明当时只给它们随 n 增长的有限承载。
V6 本身也在 L0：它的末项6正是封闭 c 的高2工作入口，父表为 \((c,r)\)。
新增[统一索引闭包](RECURSIVE-INDEXED-CLOSURE.zh-CN.md)已经把全部旧 J_d
统一到一个有限承载以下，但仍未控制 L0 这类额外的行1工作返回。

因此，若要用 d 对 L 作归纳，基例已经要求处理任意多次跨高1保护根的递归工作。
不能以“重置成0”略去这些工作，也不能把较低初始宽度当成所有未来调用宽度下降。
一种可能的继续路线是把组件的序数工作量与同根封闭链共同计入预算；
另一种是利用新增的递归闭包承载。本文没有给出到这些新资源的完整源端比较。
单个索引模板仍受其本轮底库限制，更高端点必须通过新母模板付费另开一轮，不能免费重用。
