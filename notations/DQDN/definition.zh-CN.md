# DQDN：增量有类型图的候选定义与验收 · [English](definition.md)

2026-10-06 发布整理，沿用 2026-10-05 的研究规则；当前有 Python 核、独立 NER 展开器和纸面论证，**没有 Lean 证明或独立数学审稿**。

使用入口见 [README](README.zh-CN.md)，[良序证明](../../proofs/paper/dqdn-well-ordering.zh-CN.md) 与 [定位及比较结论](../../research/dqdn/README.zh-CN.md) 分开保存。

## 1. 为什么采用这个版本

普通计算只需 λ、应用、自然数、后继、递归和询问。更高强度来自允许
不同阶的多态类型结构，而不是在一个旧大序数外面取幂。
类型层只负责规定可以生成什么程序；运行时擦去类型，不在基本列一步里
执行昂贵的完全正规化。

较早方案采用完整显式证书（不属于本发布定义）。当前版本改为
**增量有类型构造**：每次只根据已有合法对象生成一个新对象，立即存下其
类型和程序图。因此不需要最后重做整份证明的验证，也不隐藏巨大推断类型。

## 2. 一列的大小

每列是一个有限种类标签，加至多三个左指针；数字、变量距离和生成层号
作为带标签的自然数原子存储。较长记录拆成几个小节点。

- 普通程序节点：变量、数字、λ、应用、后继、递归、查询。
- 类型节点：Nat、类型变量、箭头、∀、类型 λ、类型应用。
- 小管理节点：kind、环境、带类型对象、类型等式、库链、未填完的参数表。
- 活动列 `!p`：对前面的源节点 p 作一步操作。

程序、类型和环境都是当前对象的邻接图；不是把展开操作历史重新编码。
类型对象可能跨许多列，但不会把整棵类型树塞进某一列。

## 3. 普通计算只有五条

$$
(\lambda x.t)u\to t[u/x],\quad
S(n)\to n+1,\quad Q(n)\to m\ (m\in\mathbb N),
$$
$$
R(z,s,0)\to z,\qquad
R(z,s,n+1)\to sn(R(z,s,n)).
$$
按名、按需选位置：应用先看函数头；S/Q 先看数字参数；R 只先看第三参数；
不进入 λ 体，不预先计算实参。找一个位置不等于运行到正规形。
类型换元和普通 β 换元都要防止变量捕获。

## 4. 分层生成器

kind 为 * 或 κ→λ，高度为这棵 kind 树的高度。
层 0 只允许 Nat、函数类型及原始递归。层 k≥1 允许 Fω 的类型规则，
但所有 kind 高度小于 k。它比较的是类型结构，不是行号与列号。

源 `G(k)` 选择一个有限燃料 b，转入 `B(k,b,L,pending)`。
初始库 L 只有空环境、基本 kind、Nat 及数值 0 等固定基础对象。

当 b>0：

1. 没有待办构造时，选择一个有限种类的构造规则。
2. 逐个选择它需要的参数。环境、类型、项、kind、等式引用库中现有同类
   对象；数字参数才取任意自然数。
3. 参数齐备后执行这一个局部构造。适用则加入新对象，不适用则该分支终止于 0。
4. 上面每一次选字段或执行构造，都将燃料减 1。

b=0 时，运行库中最后一个闭的 Nat 程序；不存在则运行 0。
未完成的参数表直接丢弃，不做补全搜索。

可选构造就是通常的 Fω 判断规则：kind/环境扩展，Nat/变量/箭头/∀/
类型 λ/类型应用，项变量/数字/λ/应用/多态抽象/实例化，以及 S、Q、R。
等式构造允许反身、对称、传递和**指定地址的一次类型 β/η 步**；项可沿
一个已有类型等式转换类型。原型共列出 28 个局部构造入口。

这 28 个入口属于真实规则成本，不能只报“五条运行规则”就说系统已与 RPD
一样简单。部分入口只是同一判断规则的管理拆分，可进一步合并，但本轮尚未
证明能把整个类型层压成 RPD 式的几条统一图规则。

所有推断结果实际写成图节点。单次类型实例化即便使类型变大，其大小也会
出现在当前式子里；不存在指数大的隐式类型在后台免费增长。

## 5. 基本列封装

数据列都是后继列，活动列才是极限列。

- 空串为 0。
- 末列是数据时，所有 `[n]` 都删掉它。
- 末列是活动时，先删除它，再依次写入前 n 个一步孩子块。
- 每块先写一个数据标记，再补孩子缺少的共享节点，最后写孩子活动列；
  孩子已停止时只写第二个叶数据。

每个源孩子要反复出现。原型用一个不打包大整数的公平指标函数：

```
c(0) = 0
c(2m+1) = m
c(2m+2) = c(m)
```

每个 m 在 2m+1 之前首次出现，并通过 i↦2i+2 再出现无限次。
这比三角形轮询的首次出现更快。它改变孩子排列，不改变源树秩。

因此 `[0]` 删末列，`[n]` 是 `[n+1]` 的结构前缀，每个非后继式子的
第 n 项长度至少为原长度减 1 再加 2n。一次展开的输入、输出和中间图大小
对实际输入位长与 n 都有多项式上界；不会执行完整的程序或类型正规化。

## 6. 公共标准域与比较

定义 Pₖ 为依次放入 `G(0),!G(0),G(1),!G(1),…,G(k),!G(k)` 的列串。
标准式是某个 Pₖ 的有限展开后代，包含通过 `[0]` 取得的所有前缀。

原型另提供一个单列顶端 TOP：`TOP[0]=空串`，`TOP[n+1]=Pₙ`。
它的基本列恰有 2n 列，也满足前缀关系。顶端表示整套下段的上确界，
不把这个额外最大元算入下段序型；计数视图中 TOP 写成单个 2，普通
非空标准式都以 1 开头，故同样可用字典序比较。

在这个共同标准域中，数据记 1、活动记 2，普通字典序单射且等于展开序。
**不能**把任意两个独立编写的程序图仅凭相同计数字就合并进来。

标准性也能计算。对长 L 的候选，只须考察 P_L：更大根在前 L 列之外
的操作若最终留下一个 L 列式子，必先全部删除，不能改变这部分的可达性。

从根与候选的最早不同列开始：

1. 候选已是当前串的前缀，则合法。
2. 若最早不同处不是“当前活动列，候选数据列”，则不合法。
3. 删除该处以后的当前列，再展开足够多个孩子，使输出长度超过 L。
   比较这个固定无限拼接流的有限前缀，重复。

每次成功至少多固定候选的一列，最多 L+1 轮。原型 `is_standard` 实现了
这个判定。资源不足会抛异常，不把“没算完”误判为非标准。

## 7. 良序性与 ≥PTO(Zω)

每一个局部构造保留其类型判断。类型 β/η 步只改变指定位置，服从通常
的 kind 保持与换元引理。因此库中最后选出的闭 Nat 程序属于 Fω+Nat+Rec。
可数查询 Q 的每个数字结果均可归约；可归约候选证明扩展到这种查询。
这给出其整个源关系良基，而不只保证每个固定一致 oracle 的执行终止。

生成阶段的燃料严格下降，然后进入上述程序，所以每个 G(k) 良基。
设其源树秩为 h，数据列赋值 1、活动列赋值 ω^h，按列取序数和。
公平重复保证基本列严格下降且共尾。共同根的前缀性质进一步保证这个
估值是标准下段的真实序型，而非宽松上界。

每个有限 Fω 类型推导都可按其依赖次序用这些构造生成：β/η 转换展开成
有限局部步，环境的中间对象保存在图中，最后使用足够的有限燃料。

再用 [Girard 接口稿](../../research/dqdn/girard-oracle-bridge.zh-CN.md)：从任意 Zω 可证原始递归良序抽取
带自由函数参数的下降失败位置程序；查询树秩下界被活动列的 ω^h 吸收。
于是纸面上得到

$$
\sup_k |P_k|\ge\mathrm{PTO}(Z_\omega).
$$
这是使用标准函数解释接口的纸面论证，不是 Lean 认证。原型测试也不能
代替全部 28 条局部构造及其完备性的形式化证明。

### 7.1 针对无穷降链的审计补充

这里的数学论证针对第 6 节的 **TOP 可达标准域**。不把 `expand` 能处理的
所有裸图都当作合法式，也不把计算预算耗尽解释为找到降链。

1. 初始库的判断正确。28 个局部入口分别是环境/类型/项构造，以及类型的
   βη 等式规则。关键侧条件包括：λ 应用的参数类型匹配、递归步类型匹配、
   ∀ 引入时环境不得含被泛化变量、类型 η 收缩时被删除变量不得自由出现。
   代码的负移位检查执行后两项；变量、λ、类型换元采用捕获规避的索引操作。
   所以，归纳到每个成功的有限构造，输出仍有 Fω+Nat+Rec 的类型推导。
2. 对普通程序使用扩展的强正规化论证，而不只使用“每个固定 oracle 都停机”。
   扩展关系包含 `Q(n)→m` 的**所有**自然数 m，允许同一位置回答不一致。
   Girard 归约候选的中性项闭包要求所有一步后继都可计算；数字都是 Nat
   的可计算项，因此该闭包允许 Q。对 Q 的参数归约作良基归纳；原生 Nat
   递归器使用其通常的可计算性引理。这里用良基归纳，不能错误地假定整棵
   可数分支树有统一有限的最大运行长度。由类型归纳，所有闭有类型程序在
   这个扩展关系下仍强正规化。DQDN 的按需步骤只是该关系的一部分。
3. 每条 G(k) 路径先选择一个有限燃料；B 每次消耗一个燃料，然后停止或
   进入闭有类型 Nat 程序。没有生成 G/B 程序节点的项构造规则。因此普通
   程序不能跳回生成器补充燃料，G(k) 自身也没有无限路径。
4. 源关系良基后，在通常集合论背景下赋予树秩 h。数据列权重 1，活动列
   权重 ω^h，整个式子按列作序数和。展开末活动列只产生有限多个、秩严格
   更小的孩子活动列和数据列；其总权重严格小于被替换的 ω^h。删数据列
   同样严格下降。TOP 取所有 Pₖ 值的上确界，每个 Pₖ 严格低于它。
5. 共同根的确定性前缀展开保证：两个标准式在最早不同计数列处，较小者
   是该处活动前缀的展开后代。因此上述序数赋值严格保标准域字典序，排除
   任意字典序无穷降链，而不只是排除连续基本列操作产生的链。

由此，当前数学方案的纸面结论是标准域全段良序。它不是之前允许非良序
部分、只要求良序部分共尾于 ω₁ᴄᴋ 的方案。本次没有发现合法反例。
这仍不是已经通过机器验证的程序正确性定理：类型核、强正规化扩展和
可达域保序都没有 Lean 认证；有限测试不能消除所有实现漏洞。

研究时额外测试为 [`audit_wellfounded_boundary.py`](../../research/dqdn/code/audit_wellfounded_boundary.py)：1,000 组项换元和 1,000 组
类型换元，与独立的“抬升—替换—下降”三遍定义对照；拒绝错误 η 收缩；
更深的可达式计数字碰撞/下降检查；以及下列负对照。四项测试约 0.7 秒，
原有 31 项测试也通过。没有改变生成或展开规则，没有后台长搜。

负对照：去掉标准域限制，令 Δ=λx.xx、Ω=ΔΔ，则 Ω→Ω。对应五列裸图

```text
[v(0)][a(0,0)][l(1)][a(2,2)][run(3)]
```

反复 `[1]` 会在末活动列前再加一个数据列，计数字依次为 `11112`、
`111112`、`1111112`、……。这是裸图域的真无穷降链，但起点与所有这些
后代均被 `is_standard` 排除，不是 TOP 可达域的反例。这里不声称它是
所有裸图反例的字典序最小者。

### 7.2 擦除、共享与生成器边界的进一步核对

类型擦除不能仅凭“带类型程序终止”一句带过。这里可直接采用擦除项的
隐式类型判断 `Δ;Γ ⊢ e:A`：∀ 引入/消去只改变判断，不改变 e；项 β、S、Q、R
是第 3 节的五种规则。归约候选的基本引理直接对这个判断的推导归纳。
因此不需要假设一个擦除步骤恰好对应一个显式类型程序步骤，也不把已擦除的
类型归约当作隐藏的运行操作。转换规则的依据始终是有限、合法的类型 βη 等式。

另一个独立接口是“共享 DAG 的一步确实是上述擦除项的一步”。把有限左指针
图展开成出现位置树作为证明工具（实现不这样展开），按需求值找到的是一个
确定出现位置；只重建从该位置到根的路径，别处共享节点不受修改。β 换元
按绑定深度缓存，不能把同一节点在不同深度下的结果混为一谈。由图的有限性
及捕获规避换元引理，展开后的结果树等于在该位置做一次树归约。因此图若有
无限计算，就给出有类型擦除项的无限计算，与 7.1 的基本引理矛盾。

特别地，同一 `Q(0)` 数据节点的不同出现位置可以得到不同回答；不是一致的、
全局记忆的 oracle。例如

```text
R(Q(0), λk.λx.x, Q(0))
```

首个回答 1 只替换递归索引处的 Q；基例处的 Q 保留，后来可以回答 2。
全回答强正规化论证必须覆盖这种路径，不能只用固定函数 oracle 的终止性。

生成器也没有从相邻图列偷取未验证程序的入口：选参只遍历当前 library 的
可达对象，不遍历整个列串或整个节点仓库；初始库和每次成功构造都不产生
以 G/B 为程序构造子的项。生成器状态的共享不改变其有限燃料，也不能被
擦除项当成“补充燃料指令”调用。

新增的两项测试分别核对共享 Q 的不同回答，以及六个独立检查过注释类型的
程序（含多态恒等函数的自应用、ε₀ 源、有限塔）之擦除图与树解释的短步前缀。
每条轨道至多 48 步，展开成树至多 20,000 节点；并非长时间试运行来猜终止。
加上原有测试共 37 项通过。这些结果支持实现符合论证，但没有取代一般引理
或完成强正规化的机器认证。

## 8. 哪些短式子是真正校准过的

- 独立普通源 E 的图加活动共 21 列，列序数恰为 ε₀；保留已选 ω 前缀则
  22 列。[塔轮廓稿](../../research/dqdn/tower-profiles.zh-CN.md) 给出不依赖一般上界的特定塔族证明。
- 全局 P₀ 只有 `G(0),!G(0)` 两列，其值恰为 ε₀。上界使用 System T
  查询树的统一 type-level 界，下界用上述有限塔族；有限生成燃料不会越过 ε₀。
  参见 [Xiao–Sun，Theorem 1.1](https://arxiv.org/html/2609.20369v1)。
- 更高 Pₖ 同样短；精确序数和最小公理上界未校准。后续 BO/BMS 下界见[研究总览](../../research/dqdn/README.zh-CN.md)，不得将下界写成等号。

P₀ 的规则是“全部简单类型”，不是 ε₀ 特判。也没有为 BO/BMS 加专用节点。
单独的短图不自动成为全局域中的同一个短名字；前置兄弟块的贡献必须计算。

## 9. 目前的验收结论

硬结构要求已有统一方案和研究原型：列序列、字典序、末列改造、`[0]` 删除、
前缀基本列、容易识别后继、多项式单步及线性以上输出增长。

主要未达标项仍是**完整规则简洁性**。类型库比 RPD/ARD 的原生图结构重。
自然层级边界可短写，不能推出所有常见或尚未知“整序数”的精确式子都短。
已有计数序列、完整列列表、最简操作序列、增列序列四种 NER 展示；研究时的 1,504 次展开与 Python 对照一致，
尚未在实际网页中实测。仍没有完整独立证明审计或形式化，不宜称为最终成品。
