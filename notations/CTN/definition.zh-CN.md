# CTN 概括表伪序记号 · [English](definition.md)

**CTN = Comprehension Table Notation。** 本目录采用原研究名 CTN2 的线性基本列规则，2026-10-01 正式改名为 CTN。最初名为 CTN 的旧展开规则作废，不作为另一个版本收录；这次改名不改变原 CTN2 的合法域、排序、展开或显示。

CTN 是一个可计算的**伪序记号**：整体不良序；已有[纸面论证](../../proofs/paper/ctn-well-founded-part.zh-CN.md)给出最大良序初始段恰为 $\omega_1^{CK}$。这不是全体良序证明，也不是 $\mathrm{PTO}(Z_2)$ 的定位。没有 Lean 形式化；本包的有限测试不能证明 CK 结论。

## 1. 表达式与顺序

每列只有 `1` 或 `2`。表达式是有限列串，空串为零。比较是普通字典序，`1<2`，真前缀小于其延长。单列 `2` 是全系统顶端，**不是真实序数，也不等于 CK**。

不是任意二值串都合法。合法域由下一节的有限表检查器精确给出；合法不意味着处于良序段，也不意味着相应表可以无限延长。

## 2. 有限逻辑表

表的实际值是自然数。四类信息为：集合成员位 $M(i,n)$、公式真值 $V(\varphi,N,S)$、存在见证 $W(\varphi,N,S)$、概括集合编号 $C(\varphi,N,S)$。$N,S$ 分别为数变量值和集合编号的列表，不混用两种变量。

有限表检查五类规则：

1. 原子算术直接核算，成员公式读取 M。
2. 否定与合取的真值服从布尔运算。
3. 真存在式的 W 必须给出一个真实例。
4. 假存在式的每个已经可检查的实例都必须为假，数与集合量词同理。
5. C 指定的集合成员位与相应公式的真值一致。

**只查已经出现且依赖格齐全的义务；缺格就暂缓。** 不搜索模型、不运行真值判定器、不等待某程序停机。沿无限表，每个固定义务及其依赖最终都会出现。

为避免任意编码黑箱，固定 Cantor 配对

$$p(a,b)=\frac{(a+b)(a+b+1)}2+b.$$

空列表编码为 0，非空列表编码为 $1+p(\text{首项},\text{尾码})$。公式码为 $p(\text{操作号},\text{参数码})$，多参数右结合配对。一元参数直接取自身的码。

| 操作号 | 公式 | 参数 |
| --- | --- | --- |
| 0 | 数变量为零 | i |
| 1 | 相等 | i,j |
| 2 | 后继 | i,j，表示 $N_i+1=N_j$ |
| 3 | 加法 | i,j,k |
| 4 | 乘法 | i,j,k |
| 5 | 成员 | i,j，表示 $N_i\in S_j$ |
| 6 | 否定 | 子公式 |
| 7 | 合取 | 两个子公式 |
| 8 | 存在数变量 | 子公式 |
| 9 | 存在集合变量 | 子公式 |

变量采用 de Bruijn 编号；0 号是环境首项，实例化只在对应变量类型的列表前加见证。记 $q=p(\varphi,p(N,S))$：

| 地址 | 内容／义务 |
| --- | --- |
| $p(0,p(i,n))$ | M(i,n) |
| $p(1,q)$ | V，以及原子、布尔或真存在检查 |
| $p(2,q)$ | W；非存在式只能填 0 |
| $p(3,q)$ | C；公式在多一个数变量的环境中检查作用域 |
| $p(4,p(q,n))$ | 本格为 0，检查第 n 个概括实例 |
| $p(5,p(q,n))$ | 本格为 0，检查第 n 个假存在实例 |

保留地址与无效语法对应格填 0。长度 m 的表只核查地址 $0,\ldots,m-1$。需读地址不小于 m 时暂缓，不按那个大地址分配数组。完整实现是 [ctn_table.py](ctn_table.py)。

记通过检查的实际值表之树为 T，实际值 a 在列串内用正整数 a+1 编码：

$$U=\{s:(\forall i<|s|)\ s_i>0\ \land\ (s_0-1,\ldots,s_{|s|-1}-1)\in T\}.$$

空表属于 U。编码值 0 在**每个节点**都是终止分支，不是仅为 ω 添加的特例。

## 3. 合法域

令 $b(k)=1\,2^k1$，$E(s)=b(s_0)\cdots b(s_{m-1})$。这里幂只表示实际字符重复，不是序数乘方。合法式恰为以下五类：

| 形式 | 条件／含义 |
| --- | --- |
| E(s) | s∈U，表入口 |
| E(s)2 | s∈U，封口 |
| E(s)1 2^k | s∈U，k≥0，未闭合块 |
| E(s)2 1^j | s∈U 非空，j≥1，非根封口的后继链 |
| E(s⌢k)1^j | s∈U，s⌢k∉U，j≥0，失败孩子的终止链 |

封口后的后继尾巴、失败候选后的 `1` 都不继续填逻辑表。全系统顶端 `2` 上不再加尾巴。域对原始列前缀封闭，全部合法式都由顶端有限展开可达。

## 4. 基本列

空式展开仍为空；非空式统一令 $A[0]$ 为删末列。下列 n≥1，P 表示旧串删末列后的前缀：

$$ (P1)[n]=P. $$

$$ (E(s)2)[n]=E(s)1\,2^{n-1}. $$

未闭合块的末列 2：若 $A=E(s)1\,2^{k+1}=P2$，则

$$
A[n]=\begin{cases}
P12\,1^{n-1},&s^\frown k\in U,\\
P1^n,&s^\frown k\notin U.
\end{cases}
$$

| A | A[0] | A[1] | A[2] | A[3] |
| --- | --- | --- | --- | --- |
| `2` | 空 | `1` | `12` | `122` |
| `12` | `1` | `11` | `111` | `1111` |
| `122` | `12` | `1212` | `12121` | `121211` |
| `12121` | `1212` | `1212` | `1212` | `1212` |

对合法非空式，末列为 1 **当且仅当有直接前驱**；末列为 2 则没有直接前驱，在良序段内才解释为极限序数。每一步严格字典序下降。$A[n]$ 是 $A[n+1]$ 的完整列前缀；末列为 2 时

$$ |A|-1+n\le |A[n]|\le |A|+n\qquad(n\ge1). $$

从第 1 项以后每增加一次下标恰增加一列，故 $A[\infty]$ 是真实的无限前缀并集，不是另一个有限合法式。严格大小也恰等于非空有限展开可达性。

## 5. NER 与两种计数

将 [CTN.ne-rewritten.js](CTN.ne-rewritten.js) 导入 [NER](https://smilelee-lyx.github.io/ne-rewritten/) 的“自定义记号”，名称为 **CTN**。新 ID 为 `ctn-linear-20261001`；请停用本机旧的 CTN／CTN2 文件，避免在菜单中同时保留过时副本。原 CTN2 保存的原始 1/2 串仍可输入；初版 CTN 的式子不能据名称直接沿用旧序数值。

保留六种显示：原始列（计数序列）、列列表、分组简写、有限表、1 前连续 2 数、分块计数（后 2 数加一）。

- 实际逐列清空计数就是原始的 1/2 串；这里只清空当前列位置，不累计新追加后缀的全式下降时间。
- 每个 `1` 前紧邻的 `2` 个数不是逐列计数；末尾未闭合的 `2` 必须另外保留。
- 将 `1` 及其后 k 个 `2` 视为一块，其清空计数为 k+1。例如 `1221` 显示 `3,1`。这是分块副视图，不能拿它的长度替代真实列数。

只有原始列／列列表支持输入，`0`、`∅`、`[]` 表示空式。三种 FS 接口完全相同。网页保护维持原值：20 万列、100 万输入字符、约 600 ms 单次预算及 300 万计费操作；超限只报错，不截断结果、不改变数学规则。

Python 核 [ctn.py](ctn.py) 仅依赖同目录检查器与标准库，没有网页保护；大输出仍需调用者自行设界。按真实输入列数 L 计，纸面保守上界为 $O(L\log^4(L+2)+n)$ 时间、$O(L+n)$ 空间；不是关于二进制下标长度 log n 的界。

## 6. 定位与复核

自然数 m 为 m 个 1，`12=ω`；32 列的 ω²、56 列的 ω³ 及 ω^ω 的精确稀疏式见[小序数定位](small-ordinals.zh-CN.md)。ω^ω 的完整串有 69,593,927 列，不适合默认网页加载；ε₀ 尚未具体定位。没有新增算术记号分支来伪造短式。

仓库根目录运行：

```sh
python -B -m unittest discover -s tests -p 'ctn_*.py' -v
node tests/ctn.cjs --print-reference-script | python -B - | node --max-old-space-size=256 tests/ctn.cjs --fixtures-stdin
python -B notations/CTN/locate_omega_omega.py
```

这些检查不依赖私有工作目录，不生成巨大原始串，不执行无界下降搜索。证明／测试范围和来源见 [VALIDATION](../../VALIDATION.zh-CN.md) 与 [SOURCES](../../SOURCES.zh-CN.md)。没有给 CTN 新增 Lean 项目或 PDF，也不修改其他记号的证明。
