```lean
IPD.standard_wellFounded : WellFounded IPD.StandardLt
```

`Standard G` 直接定义为：G 是某个实际种子 `seed n` 经有限次实际 `expand` 得到的后代。定义没有加入 `Acc`、良基性、语义可表示性或证明证书。`StandardLt` 就是实际列列表的字典比较；`TermLt` 再加一个最大 TOP。

另有 `IPD.Semantics.valid_step_wellFounded`：所有结构合法辅助图上的严格基本列展开关系良基。**不**声称所有手写合法图的全局列序良序。

## 2. 数据的双向编码

每一列是一个有限边列表。一条边由父列 p 与轮廓 (d,t) 组成。Python 写成 `(p,(d,t))`，JS 写成 `[p,d,t]`，Lean 写成 `Edge.mk p ⟨d,t⟩`。

第零层的 t 是自然数地址。正层树有以下逐构造子的对应：

| 数学对象 | Python | JS 共享池 | Lean |
| --- | --- | --- | --- |
| 第零层 ROOT/SELF 地址 | 自然数 | 自然数 | `Layer Nat 0` |
| 正层零树 | `()` | ID 0 | `Tree.zero` |
| 正层 CAP 头 | `-1` | `-1` | `WithTop.top` |
| 普通头 | 低一层树 | 低一层树的 ID | `WithTop.coe` |
| 非零树 | `(head,children)` | `make(d,head,children)` 的 ID | `Tree.node head children` |

解码共享池时只沿已建立的有限节点结构递归；节点 ID 本身不参与非零树的大小比较。池的驻留键包含层、头与有序子 ID，故相同结构得到相同 ID。不同层的零树、ROOT0、CAP 不混同；其类型由当前层决定。

Python/JS 的合法边条件正是 Lean 的 `Edge.Valid j`：p<j，且每一个第零层引用 i 满足 i≤p 或 i=j。检查递归进入普通头和全部子项。规范列按父严格递减，同父只留最大轮廓。

因此，在规范的合法列数据上，三种表示之间存在直接递归的双向翻译。JS 的缓存、共享、字符串重复缩写不改变解码值。这里不把浏览器或 Python 的任意动态对象当作数学语法；范围是上述有限构造子组成的合法项。

## 3. 比较对应

树比较的分支顺序完全相同：相等、零树、左子项屏蔽、右子项屏蔽、头、元数、首个不同的子项。Lean 的 `Tree.cmp_node_rule` 已证明这个实际分支方程与数学 LPO 全序一致。

普通头比较递归降低层；同层子项比较递归进入真子项。因此该有限分支方程唯一决定参考程序的结果。轮廓先比较 d，再比较同层树；图按列从左向右，每列先比较父再比较轮廓，最后按真前缀比较。

控制边是另一顺序：先轮廓、再父。`controller_max` 验证这一点；证明没有把列比较误当作控制顺序。

## 4. 降低对应与 JS 剪枝

Lean `Tree.lower` 对全部原子项递归，零项返回 `none`，对应 Python 跳过零项。正层非零项永不返回 `none`，由 `Tree.lower_none_iff` 保证，所以 Python 的非零子项候选不会意外包含 `None`。

内部种子、CAP 的较小头、普通头的递归降低、初始最大值、较小元数候选、较小头候选、原头的每个换位候选，及恰好 n+1 轮闭包，与 Python 逐项相同。`replacements` 的递归写法正好枚举

$$
(a_0,\ldots,a_{i-1},u_i,M,\ldots,M)
$$

而不是降低新生成项。跨层最小项改成低一层种子；最小第零层项删除边。

JS 仅保留最右的非末非零位置与非零末位置。其精确等价证明见 [主证明 §10](ipd-well-ordering.zh-CN.md#10-与-pythonner-规则的对应)：每轮 M 不小于全部原子项；较右非末候选包含 M 作为真子项，因而严格压过所有较左候选。末候选可能不含 M，必须单独保留。

这一论证对任意有限合法树成立，不是由有限测试推测。对原树、层及轮数归纳，保留候选的递归值相同，被省略候选都不改变最大值，故 JS 与全位置定义返回同一数学项。

验收边界：Lean 直接形式化了全位置数学算法；没有把 JS 虚拟机、共享池实现及剪枝程序的逐条机器指令形式化。这里的源语言对应与剪枝等价是明确给出的纸面语义证明，不能称为“Lean 直接编译认证了整个浏览器程序”。

## 5. 规范化和展开对应

Python/JS 的字典式规范化与 Lean 的插入式规范化都由同一个唯一规格确定：父集合恰为输入父集合，每个父的轮廓是其所有输入轮廓的最大值，父按严格递减排列。

插入式规则逐项验证该规格：遇到较小父就在其前插入；遇到同父取两轮廓最大；遇到较大父保留它并递归。对输入列表归纳即得整个规格。字典式规则则对每个父独立取同一个最大值。由于轮廓是全序、同父唯一，这一规格唯一，故两种规范化相同；相等最大值对应同一树结构，而非隐藏的任选代表。

令 x 为旧末列、c 为控制父、L=x−c，移动为 phi_b(i)=i（i<c）或 i+bL。原程序循环顺序与 Lean 的块列表顺序对应如下：

- 原程序的第 0 份来源列合成 `G.take x`；规范输入在这部分不变。
- Lean 的第 b 个新块，恰是原程序的第 b+1 份来源列 c,…,x−1。
- 该新块首列 x+bL 还拼入原程序第 b 个接缝。原程序先写接缝后写下一来源列，Lean 把来源列放在接缝之前；二者经上面的唯一规范化得到相同结果。
- 两边都先移动整棵轮廓，再以移动后的父、SELF 和块号 b 降低控制父上的边；没有冻结头树或使用旧地址降低。
- 输出列数同为 x+nL。第 0 项和空末列都删除末列，空图保持空图。

这给出对任意 n 的分块对应，不依赖运行多少步之后终止。`GraphGeometry` 与 `SpliceLabels` 检查移动组合；`StageSplice` 检查整个真实结果的旧边、来源边、接缝边，而非只检查局部末列。

种子都是两列的最小层轮廓，`seed_succ_one` 已核验 A_(n+1)[1]=A_n。TOP[n]=A_n。由一步对应归纳，三种实现的标准可达域一致。

## 6. 证明的依赖及没有作出的主张

证明链为：实际轮廓良基 → 实际有限需求递归 → 实际最小 Bad/Ext 见证 → 可数向下闭包 → 端点一致性 → 初始表示供应 → 整图展开降低末标签 → 展开良基 → 标准域按列良序。

最终 Lean 定理的公理报告只有 `propext`、`Classical.choice`、`Quot.sound`，没有 `sorryAx`、自定义良序公理、反射公理或大基数公理。中间文件中的接口前提都在最终定理中用已证明的 IPD 结果实例化。通用的闭包、序数高度及可达性库复用了项目已有文件；没有使用 Y 或 ARD 的良序定理替代 IPD。

纸面上界为 KP_omega＋存在不可数序数，含完整集合归纳；[主证明 §12](ipd-well-ordering.zh-CN.md#12-与-lean-相同的显式见证闭包版本) 给出与 Lean 见证闭包同路的弱体系论证。这个上界没有在 Lean 内部编码，不从 Lean 的公理报告反推出 KP。

本次没有证明 IPD 与 wY、TPD 等的大小关系，没有证明最弱公理界、PTO 比较或基本列共尾性。显示计数、绘图及其优化不参与数学项与列比较。

运行保护触发时 FS 抛出异常，不返回截断数学项。无限自然数规则与有限硬件上能否完成某次求值是不同问题。两个冻结展开器中的“研究中”说明是冻结时的历史注释，当前证明状态以本文件及 Lean 验收记录为准。
